# Мониторинг в DevSecOps — Prometheus

## Prometheus

**Prometheus** - это база данных временных рядов, предназначенная для мониторинга систем и инфраструктуры.

Prometheus может мониторить:
- сервера
- базы данных
- виртуальные машины
- приложения
- контейнеры и др.

Prometheus периодически получает метрики от целевых объектов через HTTP-запросы. Этот процесс называется **scraping**.

## Работа Prometheus

Для получения метрик используются несколько способов:

### Инструментирование

В приложение добавляются специальные клиентские библиотеки Prometheus. Приложение начинает предоставлять метрики по определённому URL, после чего Prometheus забирает их.

Инструментирование поддерживается для многих языков программирования:
- Python
- Java
- Ruby
- Go
- Node.js
- C#

### Экспортеры

**Экспортеры** позволяют получать метрики от уже существующих систем, приложений и баз данных.

Примеры:
- Node Exporter - метрики Linux
- MongoDB Exporter - MongoDB
- SQL Exporter - SQL-базы данных
- HAProxy Exporter - HAProxy

### Pushgateway

Эта штука используется в ситуациях, когда приложение или отдельное задание не может напрямую предоставить метрики Prometheus.

## Сбор и отправка данных

Главная особенность Prometheus в том, что он сам собирает метрики с целевых объектов.

Это отличается от систем, где приложения сами отправляют данные на сервер мониторинга.

Преимущества подхода Prometheus:
- централизованное управление
- можно задавать частоту сбора метрик
- можно использовать разную частоту сбора для разных объектов
- можно контролировать объём собираемых данных

Prometheus в основном работает с **агрегированными метриками**, а не с отдельными событиями.

Вместо хранения каждого события ошибки HTTP можно хранить количество ошибок `404` за определённый период.

## Экосистема Prometheus

Prometheus можно расширять дополнительными инструментами.

### Alertmanager

Он отвечает за обработку и отправку оповещений.

Правила оповещений задаются в конфигурации. Если метрика соответствует заданному условию, создаётся оповещение.

Получателями могут быть:
- электронная почта
- Slack
- PagerDuty
- HTTP-объекты

### Визуализация

Метрики можно просматривать и анализировать через веб-интерфейс Prometheus. Также для визуализации часто используется Grafana.

### Обнаружение сервисов

Prometheus может автоматически обнаруживать новые целевые объекты.

Это особенно полезно в контейнерных и распределённых системах, где экземпляры приложений могут часто создаваться и удаляться.

# Основные понятия Prometheus

## Модель данных «ключ-значение»

Prometheus хранит данные в виде:

**метрика -> числовое значение**

Метрика показывает, что именно измеряется:
- загрузка процессора
- использование памяти
- количество HTTP-запросов

Для дополнительной информации используются **labels**.

С помощью ярлыков можно указать например:
- IP-адрес
- ядро процессора
- экземпляр приложения
- задание

После этого метрики можно фильтровать по ярлыкам.

# Типы метрик

В Prometheus существует четыре основных типа метрик:

1. Counter - счётчик
2. Gauge - измеритель
3. Histogram - гистограмма
4. Summary - сводка

## Counter

Он используется для подсчёта количества событий.

Например:
- количество HTTP-ошибок
- количество посещений сайта
- количество запросов

Счётчик может увеличиваться или сбрасываться.

Он подходит для событий, количество которых накапливается со временем.

## Gauge

Он показывает текущее значение, которое может как увеличиваться, так и уменьшаться.

Например:
- использование памяти
- температура
- текущая нагрузка

В отличие от Counter, Gauge подходит для значений, которые могут изменяться в обе стороны.

## Histogram

Она используется для распределения значений по диапазонам.

Она позволяет получить:
- количество измерений
- сумму измерений
- распределение значений

Гистограммы удобно использовать для анализа времени ответа и других показателей.

## Summary

Эта штука похожа на Histogram, но дополнительно позволяет получать квантили за определённый скользящий период.

Например, можно определить значение, ниже которого находятся 95% измерений.

Выбор между Histogram и Summary зависит от задачи.

Summary можно использовать, чтобы узнать значение, которое представляет **95% измерений**, записанных за определённый период, к примеру.

# Задания и экземпляры

В распределённой системе может работать несколько серверов одного приложения.

**Экземпляр (instance)** - отдельный сервер или запущенная копия приложения.

**Задание (job)** - группа экземпляров, которые выполняют одну задачу.

Например:
- job - веб-серверы
- instance - конкретный веб-сервер

Задания и экземпляры используются как labels, поэтому по ним можно фильтровать метрики.

# PromQL

**PromQL (Prometheus Query Language)** - язык запросов Prometheus.

Он используется для:
- получения метрик
- фильтрации данных
- выполнения математических операций
- анализа изменения метрик
- построения прогнозов

Основные виды векторов:

### Моментальный вектор

Содержит значения метрик на последней временной отметке.

### Вектор диапазона

Содержит значения метрики за выбранный период времени.

# Экспортеры

Это готовые компоненты, которые позволяют Prometheus получать метрики от различных систем.

Примеры:
- **Database Exporters** - MongoDB, SQL, MySQL
- **HTTP Exporters** - HAProxy, Apache, NGINX
- **Node Exporter** - системные метрики Unix/Linux

Экспортеры позволяют быстрее настроить мониторинг готовых систем без необходимости самостоятельно добавлять инструментирование.

# Оповещения

Prometheus позволяет создавать правила для автоматических оповещений.

Правила задаются в конфигурации. Когда значение метрики соответствует условию, создаётся оповещение.

Для обработки оповещений используется **Alertmanager**.

Alertmanager может отправлять уведомления на:
- электронную почту
- Slack
- PagerDuty
- другие HTTP-сервисы.

# Prometheus в DevSecOps

Prometheus особенно полезен в DevOps и DevSecOps благодаря возможности мониторить:

- сервера
- базы данных
- приложения
- контейнеры
- распределённые системы

В контейнерной инфраструктуре системы могут динамически создавать и удалять экземпляры, поэтому обнаружение сервисов позволяет автоматически находить новые цели для мониторинга.

Мониторинг помогает вовремя обнаруживать:
- высокую нагрузку
- ошибки
- проблемы с серверами
- проблемы с приложениями
- ухудшение времени ответа

# Кратко главное

**Prometheus** — система мониторинга и база данных временных рядов.

Главные особенности:

- сам собирает метрики с целевых объектов
- использует HTTP для получения метрик
- хранит числовые временные ряды
- использует labels для дополнительной информации
- поддерживает Counter, Gauge, Histogram и Summary
- имеет собственный язык запросов PromQL
- использует экспортеры для разных систем
- поддерживает обнаружение сервисов
- использует Alertmanager для оповещений
- хорошо подходит для контейнерных и распределённых систем
